# libSceHttp technical debt

### Unknown function info

- [sceHttpUriBuild](../../../core/libs/prx/libSceHttp/src/Uri.cpp) (libSceHttp) retains `//` for a non-opaque URI independently of the selected fields, following [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/a8a70da595da2a96e0410309472ba4a7eb558144/src/core/libraries/network/http.cpp#L3551-L3558). Black Myth: Wukong builds its `Scheme` header with option 1 and expects `http://` or `https://`. Other partial field combinations follow the PS4 reference and remain unverified on PS5 hardware.
- [sceHttpParseResponseHeader](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - signature follows [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Net/Http.cs); parsing and error codes follow [shadPS4's reverse-engineered PS4 library](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp), not confirmed on a PS5 title or hardware. Folded values retain their line breaks and whitespace; an empty first line starts the value scan after its line feed. A consumed byte count above `INT_MAX` throws instead of wrapping.
- [sceHttpParseStatusLine](../../../core/libs/prx/libSceHttp/src/Parse.cpp) (libSceHttp) - behaviour and error codes follow the [shadPS4](https://github.com/shadps4-emu/shadPS4) reimplementation of the PS4 library, not confirmed on a PS5 title; unlike it, no byte past `lineLen` is read
- [sceHttpUriMerge](../../../core/libs/prx/libSceHttp/src/Uri.cpp) (libSceHttp) - signature follows [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Net/Http.cs); validation, size formula, absolute/relative split and path join follow the disassembly-like body in [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp), not confirmed on a PS5 title or hardware. The base URL goes through our `sceHttpUriParse`, which removes dot segments from the base path, while the relative part is appended unswept; base query and fragment are dropped. The relative reference is only classified by its scheme and a leading `//`, and only references with `//` are validated; as in shadPS4, `//host/x` is returned unchanged instead of taking the base scheme, a reference with a scheme but no `//` (`mailto:x`) is joined onto the base directory, and `?q` and `#f` are appended to the base directory instead of the base path.
- [sceHttpUriUnescape](../../../core/libs/prx/libSceHttp/src/Uri.cpp) (libSceHttp) - signature follows [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Net/Http.cs); percent decoding, invalid sequences and error codes follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp), not confirmed on a PS5 title or hardware. Size includes the final NUL; malformed escapes and `+` remain unchanged, and decoding runs once.
- [sceHttpUriSweepPath](../../../core/libs/prx/libSceHttp/src/Uri.cpp) (libSceHttp) - behaviour follows the [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp) reimplementation of the PS4 library and its tests (including the PS4 SDK example), not confirmed on a PS5 title or hardware. It is not RFC 3986 5.2.4: a path that doesn't start with `/` is copied unchanged and a trailing `.` or `..` without a slash is kept. Unlike shadPS4, nothing at or past `srcSize - 1` is read, and `srcSize == 1` writes only the terminator
- [sceHttpRedirectCacheFlush, sceHttpsUnloadCert](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - signatures follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp) (PS4); no PS5 reference has them
- [sceHttpSetRequestStatusCallback](../../../core/libs/prx/libSceHttp/Export.cpp) retains registrations until the handle is deleted or its context terminates. Sending with a callback on the request or an ancestor throws; status transitions and dispatch timing are not implemented.
- [sceHttpSetRedirectCallback, sceHttpSetCookieRecvCallback](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - signatures follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp) (PS4), which only logs and returns 0; a null `errNum` or `detail` in `sceHttpsGetSslError` is assumed to return `SCE_HTTP_ERROR_INVALID_VALUE` like `sceHttpGetLastErrno`
- [sceHttpSetAuthInfoCallback](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - signature and callback type follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.h) (PS4); no PS5 reference has them. The `id` is not checked, as in the other libSceHttp setters
- [sceHttpWaitRequest](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - the timeout is assumed to be in microseconds and a negative timeout to wait without limit; the invalid-value error for a null handle or event array or a non-positive event count is assumed, not measured. Event queues coalesce pending bits per request and discard notifications invalidated by deletion or detachment

### Functional

- [Request framing and CONNECT](../../../core/libs/prx/libSceHttp/src/Transport.cpp) accepts manual Content-Length and Transfer-Encoding fields. Duplicate identical lengths are normalized; conflicting lengths, simultaneous length/chunked framing, missing final chunked coding and HTTP/1.0 chunked uploads are rejected. The caller supplies any pre-encoded transfer-coding payload before curl applies chunk framing. CONNECT supports numeric method 7 and string methods, authority-form targets and HTTP URL targets through the connection origin as proxy; successful tunnels expose raw bytes and ignore response framing metadata. The curl handle remains attached for connect-only I/O. HTTP and HTTPS proxies, rejection, binary EOF reads and nonblocking tunnels have loopback tests; exact console CONNECT argument and error behavior remains unmeasured.
- [CA-list snapshots](../../../core/libs/prx/libSceHttp/src/Transport.cpp) parse the HTTP context's loaded authorities into independently owned certificate handles in its associated libSceSsl context. Subject/issuer readers accept these handles. Snapshots survive trust unload and are released by FreeCaList or HTTP termination; the SSL context pool accounts for their parsed data. The two contexts retain separate trust stores. Invalid associated SSL contexts cannot produce nonempty lists. Snapshot ownership, empty-list return behavior and lifetime rules follow the existing SSL implementation and remain unmeasured on PS5.
- [TLS callback reentrancy](../../../core/libs/prx/libSceHttp/src/Transport.cpp) allows metadata and certificate queries during verification. Reading, resending or deleting the active callback request, and terminating its HTTP context, return BUSY. Abort is allowed. Exceptions become an internal TLS failure; no exception crosses the C backend. Worker cancellation and context termination release global locks before waiting for objects. These reentrancy restrictions and exception behavior have synchronous/asynchronous tests but no console measurement.
- [Remaining HTTP contracts](../../../core/libs/prx/libSceHttp/Export.cpp) are not established by public implementations: authentication integration and the unnamed 0x2000 SSL option. The PSP HTTP reference establishes nonnegative acceptance and negative veto for auth, cookie and redirect callbacks, redirect method mutation, authentication entity lifetime and the reserved save output. These contracts are cross-family references rather than PS5 measurements. Independent PS4 caller [EAWebKit DirtySDK](https://github.com/TornadoCookie/EAWebKit16-Linux/blob/3e64388cfd9a6a308b39fce8a44dd98a9452c43b/EAWebKitSupportPackages/DirtySDK/local_15.1.6.0.5/source/proto/ps4/protohttpps4.c) demonstrates negative-return cookie and redirect vetoes and response-header reads during redirect callbacks, but does not establish positive-return decisions, method mutation or the complete callback contracts. Both version setters follow the public enum and the backend capability-floor policy also used by the pending libSceSsl transport; exact console negotiation remains unmeasured. Authentication exports and the unnamed SSL option retain NotImplemented paths. Auth and callback setters reject unknown handles instead of reporting a false success; invalid auth enable values are rejected. Other public implementations largely store callbacks or return success without dispatching them; these are not compatibility evidence.

- [Nonblocking HTTP transport](../../../core/libs/prx/libSceHttp/src/Transport.cpp) runs each nonblocking request on a joined worker, retaining a bounded response chunk rather than accumulating the response. Send owns its uploaded bytes and returns after dispatch; reads and metadata queries return `EAGAIN` while pending, and propagate terminal transport failures. Request deletion and context termination cancel and join workers. Template and connection settings, including epoll bindings, are copied into children; detaching, rebinding and deleting invalidate queued notifications. Event layout (24 bytes on x86-64), IN/OUT/socket-error/HUP bits and `EAGAIN` follow [shadPS4's public HTTP declarations](https://github.com/shadps4-emu/shadPS4/blob/a2c4e68d24b6c3e5e2441cd245dbc19960a01ba4/src/core/libraries/network/http.h); PS5 epoll signatures also follow SharpProspero. OUT is reported when response headers are available, IN when body bytes or EOF become available, and errors are currently reported with socket-error or HUP bits. DNS-specific notifications and the exact console meaning of eventDetail remain unverified. Changing nonblock mode after a transfer starts returns INVALID_VALUE; Try getters/setters return BUSY rather than waiting for a held object lock. These state restrictions, callback-thread interactions, event timing, inherited bindings and per-context epoll ownership have loopback tests but no PS5 hardware confirmation.

- [HTTPS transport](../../../core/libs/prx/libSceHttp/src/Transport.cpp) verifies guest-supplied PEM/DER certificate authorities, peer names and certificate validity through mbedTLS. Host CA stores and proxy environment variables are not used. `sceHttpsLoadCert` owns copies of certificate descriptors using the existing `SceSsl::Data` layout, validates client key/certificate pairs, appends authorities while preserving an existing identity when no new identity is supplied, and updates the context trust and identity seen by later sends, including existing connections. Unloading removes the context credentials for later sends; active transfers retain their snapshot. The descriptor layout, append and identity-replacement semantics, TLS version value 5 (TLS 1.2), option bits and default settings follow public PS4 references and this project's SSL bindings, not PS5 measurements. Minimum-version selectors accept the public values 0 through 5 and apply the requested floor within the backend's TLS 1.2/1.3 capabilities; both protocol versions have forced-version loopback tests. sceHttpsSetSslVersion also applies a minimum rather than an exact selection, following [SharpProspero at 5dfdb4b](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Net/Http.cs); value 5 permits TLS 1.3. Both setters reject selectors outside 0 through 5. Their floors are combined, inherited and checked against TLS 1.2-only and TLS 1.3-only peers. Negotiating SSL 2/3 or TLS 1.0/1.1 is outside the backend capabilities. This interpretation is a public binding contract, not PS5 measurement. The client-authentication bit 0x02 controls whether the loaded client identity is supplied during the handshake, following the PSP HTTPS reference; loading credentials alone does not enable it. Mutual-TLS tests cover enable, disable and reenable. The unnamed 0x2000 option remains an explicit unsupported path. SNI can be disabled through a static adapter around the pinned mbedTLS hostname setter; the peer name is still checked through mbedTLS X.509 verification. Peer-verification callbacks receive console verification bits and SSL-library certificate handles; zero accepts the peer and nonzero rejects it, following SharpProspero. Callback chains are scoped to the invocation, including rejection and exception cleanup. Default verification includes trust, hostname and validity checks; the guest can explicitly disable supported checks. `GetSslError` translates certificate, handshake, internal and established TLS-I/O failures using the public PS4 HTTPS error categories and verification bits. Host error numbers are not returned as console SSL errors; errors outside TLS leave the SSL error outputs zero. Classification and exact PS5 error timing remain unmeasured.
- [HTTP session behavior](../../../core/libs/prx/libSceHttp/src/Transport.cpp) scopes curl's synchronized cookie store to each HTTP context, including concurrent requests, and snapshots inherited enable settings. Authentication callbacks and persistent cookie import/export are not implemented. Cookie-receive callbacks run before storage; negative returns veto only that cookie and nonnegative returns let curl apply its domain, path, expiry and prefix policy. A static adapter queues incoming cookies until outside curl's shared-cookie lock so callbacks can send nested requests. No callback is called under the shared cookie-store lock. Redirect method rewriting, cookie matching/expiry and decompression follow curl's documented behavior. Decoded body bytes are streamed while response content-length metadata describes the encoded wire length. Cookie defaults, redirect limits, TLS options, allocation accounting and error mappings remain unverified against PS5 hardware or titles.

- [sceHttpUriEscape](../../../core/libs/prx/libSceHttp/src/Uri.cpp) escapes every byte except the ASCII unreserved set in [RFC 3986 section 2.3](https://www.rfc-editor.org/rfc/rfc3986#section-2.3), independently of the host locale. Console behaviour for non-ASCII input remains unmeasured.
- [HTTP transport](../../../core/libs/prx/libSceHttp/src/Transport.cpp) implements synchronous HTTP and HTTPS with bundled curl, mbedTLS, zlib and c-ares sources: context/template/connection/request ownership, request headers, fixed-length uploads, status and response-header queries, bounded streaming reads, chunked and EOF-delimited response bodies, cancellation and per-request synchronization. Connections describe an origin; persistent socket reuse across separate request handles is not implemented. Pool accounting is not enforced. Redirects (301/302/303/307/308, bounded to ten hops), context-isolated cookie storage, gzip/deflate decoding and chunked uploads use curl. Redirect and inflate settings default on, following the public PS4 reference; cookies require explicit enablement. HTTPS redirects cannot downgrade to HTTP. Automatic proxy configuration reads the guest network-control profile; the current network-control backend reports proxies disabled, so only that profile path has runtime coverage. A manually configured profile is translated to an explicit proxy URL; host proxy environment variables are ignored. Authentication callbacks remain unsupported. Request-status callbacks use the eleven values in PS4-Store at 4d08c6e; transport phases, DNS retries, TLS failure, cancellation, exceptions and nested callbacks are tested. Callbacks are copied into children at creation, with request-local replacement/removal. Exact PS5 dispatch timing and threading are unmeasured. Redirect callbacks can read response metadata, veto by a negative return, or change the next method. The callback decision overrides the automatic-redirect setting. GET/HEAD-to-POST changes send an empty body. Redirects are bounded, retain uploads when appropriate, reject HTTPS downgrades and strip explicit authorization/cookie/host fields on origin changes.
- [Transport timeouts and errors](../../../core/libs/prx/libSceHttp/src/Transport.cpp) use curl's connect timeout rounded up to milliseconds and a steady-clock receive budget for each blocking send/read drive. This budget includes waiting for initial headers; caller idle time between reads is not charged. The bundled c-ares resolver supports cancellable DNS attempts with independent resolver deadlines and configured retries. The send budget runs from curl's pre-request callback until its POSTTRANSFER timestamp confirms that the last request byte was written; waiting for response headers uses the receive budget. CONNECT proxy negotiation remains part of curl's connection phase. The timer phases, retry policy and error mappings remain unmeasured on PS5. Abort is checked between curl polls, capped at 10 ms; host resolver cleanup can still wait for an outstanding host lookup. Header-limit exhaustion returns `OUT_OF_MEMORY`, abort returns `ABORTED` and other transport failures return the existing generic `NETWORK` error. `GetLastErrno` reports curl's host OS error. Exact console error mappings, timeout phases, pool allocation, parent-deletion busy behavior and keepalive semantics remain unmeasured. Methods, header modes, metadata pointers and no-content-length result follow [shadPS4's public HTTP reference](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp); no title or PS5 hardware validation is claimed.

- [sceHttpAbortWaitRequest, sceHttpWaitRequest](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - the abort takes only the epoll handle, as in [Orbital](https://github.com/AlexAltea/orbital/blob/master/tools/ida/db_types.json) and [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Net/Http.cs); behaviour and error codes follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp) (PS4), not confirmed on a PS5 title or hardware. An abort stays set: every later wait on the handle, a poll included, returns `SCE_HTTP_ERROR_ABORTED` (0x80431080) until the handle is destroyed. A wait woken by `sceHttpDestroyEpoll`, or by termination of its owning HTTP context, returns 0 events. The epoll calls return `BEFORE_INIT` (0x80431001) while no `sceHttpInit` context is alive and `INVALID_ID` (0x80431100) for an unknown context or handle, and `sceHttpTerm` returns the same errors instead of succeeding for any id. Epolls belong to their creating context; binding or destruction through another context is rejected. Handles are pointers, so a stale handle whose address a newer epoll reuses is taken as that epoll

- [HTTP callback contracts](../../../core/libs/prx/libSceHttp/src/Transport.cpp) follow the [PSP HTTP reference](https://github.com/xeonliu/PSP_DOCS/blob/main/network/libhttp-Reference-English.htm) and [HTTPS reference](https://github.com/xeonliu/PSP_DOCS/blob/main/network/HTTPS-Reference-English.htm). Request-status values follow [PS4-Store at 4d08c6e](https://github.com/LightningMods/PS4-Store/blob/4d08c6e6a3d54d6f35a38a830f4ec8b045ed6c43/Store-Loader/include/Http.h). Callback exceptions become transport errors and active-request deletion/read/resend and context termination return BUSY; these host safety rules are not console measurements. Installing a redirect callback after a transfer started without one returns INVALID_VALUE; an existing registration can be replaced or removed during callbacks.
